# Web Flasher (`tools/flash/`)

Static page powered by [ESP Web Tools](https://esphome.github.io/esp-web-tools/) (`esptool-js`) that lets users flash both the **PocketHID firmware** and the **built-in LittleFS PWA** directly from Chrome or Edge over USB — no PlatformIO or Python required.

**Requirements**: HTTPS (Web Serial requires a secure context) and a Chromium desktop browser (Chrome/Edge). Safari and iOS do not support Web Serial; subsequent firmware updates can be uploaded over WiFi via `http://pockethid.local/update`.

## Contents

| File | Source |
|---|---|
| `index.html`, `styles.css`, `app.js`, `icon.svg` | Unified GitHub Pages web suite: Web Flasher, Macro Studio &amp; embedded Remote PWA (committed) |
| `macros.html` | Redirect to `./index.html#macros` for legacy links (committed) |
| `manifest.json` | Regenerated by `tools/make-flash-release.sh` with the current firmware version |
| `bootloader.bin`, `partitions.bin`, `boot_app0.bin`, `firmware.bin`, `littlefs.bin` | Generated binaries (gitignored on `main`, published via GitHub Actions / Pages) |

## Automatic Deployment (GitHub Pages)

The [Release & Web Flasher](../../.github/workflows/release.yml) workflow automatically builds the PWA, firmware, and LittleFS image, attaches the binaries to the GitHub Release (on `v*` tags), and deploys `tools/flash/` to **GitHub Pages**.

To enable it in your repository:
1. Go to **Settings → Pages** and set **Source** to **GitHub Actions**.
2. Push a tag (e.g. `git tag v0.3.0 && git push origin v0.3.0`) or trigger the workflow manually from the **Actions** tab.

## Building Locally

```bash
# 1. Build and prepare the PWA in firmware/data/
./tools/deploy-pwa.sh --prep-only

# 2. Build the firmware and LittleFS image
(cd firmware && pio run -e esp32s3 && pio run -e esp32s3 -t buildfs)

# 3. Copy binaries into tools/flash/ and regenerate manifest.json
./tools/make-flash-release.sh
```

You can then serve `tools/flash/` from any HTTPS static host (GitHub Pages, nginx, Caddy, Cloudflare Pages, etc.).
